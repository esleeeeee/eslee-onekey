# 수동 시험 계획

## 사전 준비

- 비공개 OneKey 저장소 또는 로컬 게시물
- 실제 게임 실행 파일, Discord 실행 파일, 대상 헤드셋
- 배포된 Discord 봇 API의 HTTPS URL과 별도 발급 토큰
- Windows 소리 설정을 열 수 있는 시험 계정

실제 토큰/사용자 ID/개인 경로는 시험 증적에 평문으로 남기지 않습니다. 각 사례에서 로그에 `Bearer`, 토큰 값, Authorization 값이 없는지 함께 확인합니다.

## 핵심 시나리오

| ID | 절차 | 예상 결과 |
|---|---|---|
| MT-01 | 게임이 꺼진 상태에서 단축키 입력 | 원래 장치 저장, 헤드셋 전환, 게임/Discord 각 1회 실행 |
| MT-02 | 게임 실행 파일을 외부에서 시작 | 프로세스 감지로 전환, 게임 중복 실행 없음 |
| MT-03 | Active 중 단축키 반복 입력 | 중복 트리거 무시, 프로세스/세션 중복 없음 |
| MT-04 | Discord 음성 채널에서 게임 종료 | `RestorePending`, 헤드셋 유지 |
| MT-05 | MT-04 뒤 음성 채널 퇴장 | 다음 확인 후 원래 장치 복원, Completed |
| MT-06 | API 호스트 차단/타임아웃 후 게임 종료 | 헤드셋 유지, 오류 표시, 간격 증가 재시도; 복구 후 정상 판단 |
| MT-07 | Active 중 사용자가 다른 스피커 선택 후 게임 종료 | 사용자 장치 유지, 강제 복원 없음 |
| MT-08 | 트레이에서 열기/일시정지/상태/종료, UI 닫기 | 닫기는 트레이 유지, 메뉴가 각각 동작, 종료 시 프로세스 종료 |
| MT-09 | 로그인 시 시작 활성화 후 재로그인 | 최소화 실행; 비활성화 후 레지스트리 항목 제거 |
| MT-10 | Active 상태에서 앱 강제 종료 후 재실행 | 오디오 자동 변경 없음, 실패/복구 안내와 수동 선택 제공 |
| MT-11 | 이미 실행 중인 앱을 다시 실행 | 두 번째 인스턴스 안내 후 종료, 첫 인스턴스 유지 |
| MT-12 | 대상 헤드셋 연결 해제 후 시작 | 전환/게임 실행 없이 명시적 오류, 원래 오디오 유지 |

## API 경계 사례

- 올바른 토큰: 200 및 `in_voice` 불리언 매핑
- 잘못된 토큰: 401/403을 인증 오류로 표시, 토큰 비노출
- 봇 시작 중: 503을 준비 전으로 표시
- 잘못된 JSON/필드 누락: 실패로 처리하고 복원 보류
- DNS/연결 거부/5초 초과: 실패로 처리하고 재시도

## 오디오 호환성 매트릭스

가능한 범위에서 다음 조합을 반복합니다.

- Windows 10 22H2 / Windows 11 최신 지원 버전
- USB 헤드셋 / Bluetooth 헤드셋 / 내장 스피커
- 장치가 시작 전 연결됨 / Active 중 연결 해제 / RestorePending 중 재연결
- 콘솔, 멀티미디어, 통신 기본 역할이 서로 다른 초기 상태

## 합격 기준

- 어떤 실패에서도 사용자의 수동 오디오 선택을 덮어쓰지 않음
- API 상태가 불명확할 때 자동 복원하지 않음
- 중복 게임/Discord/OneKey 프로세스가 생기지 않음
- 종료/재시작 뒤 세션 파일이 손상되지 않음
- 비밀값과 고유 식별자가 설정 JSON, 로그, Git diff에 없음
