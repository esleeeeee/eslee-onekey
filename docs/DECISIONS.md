# 설계 결정

## ADR-001: WPF와 .NET 10 LTS

Windows 전역 단축키, 트레이, 레지스트리, Core Audio 연동이 핵심이므로 브라우저 래퍼 대신 WPF를 사용합니다. 신규 프로젝트 기준 현재 LTS인 .NET 10을 사용하고, 운영 배포는 `win-x64` self-contained로 게시합니다.

## ADR-002: 상태 머신을 플랫폼 코드에서 분리

복원 안전 규칙을 결정론적으로 시험하기 위해 상태 머신을 `Eslee.OneKey.Core`에 둡니다. Windows/HTTP/파일 기능은 인터페이스 뒤에 배치해 가짜 구현으로 장애와 경계 사례를 재현합니다.

## ADR-003: 실패 시 복원보다 보존

Discord 상태를 모르면 통화를 방해할 수 있는 복원보다 현재 헤드셋 유지를 선택합니다. 인증 오류도 동일하게 보존하되 사용자에게 오류 종류를 노출하고 재시도합니다.

## ADR-004: 사용자의 수동 선택 우선

복원 직전의 기본 장치가 앱이 지정했던 대상과 다르면 사용자가 바꾼 것으로 간주합니다. 원래 장치를 강제로 덮어쓰지 않고 자동화 세션을 완료합니다.

## ADR-005: 토큰은 DPAPI, 설정은 JSON

일반 설정은 읽기 쉬운 JSON으로 저장하지만 API 토큰은 포함하지 않습니다. 토큰은 Windows DPAPI `CurrentUser`로 암호화한 별도 이진 파일에 저장합니다. PC/사용자가 달라지면 복호화되지 않는 것이 의도된 동작입니다.

## ADR-006: Windows 기본 장치 전환 어댑터

장치 열거/현재 기본값은 Core Audio의 공개 MMDevice API를 사용합니다. 기본 출력 변경은 공식 관리 API가 없어 널리 사용되는 `PolicyConfig` COM 인터페이스를 어댑터 내부에 한정합니다. Windows 업데이트 호환성을 수동 시험 계획에서 관리합니다.

## ADR-007: 폴링 기반 프로세스/복원 감지

MVP에서는 WMI 이벤트 구독보다 수명주기와 복구가 단순한 1초 프로세스 폴링을 사용합니다. 복원 대기는 기본 5초이며 API 실패 시 최대 60초로 증가합니다. CPU/네트워크 비용이 충분히 작고 시험하기 쉽습니다.
